> - 新增 **7.2 逐维度详规**：每个子指标的测试数据规格、操作定义、采样方法——QA 可直接引用
> - 新增 **7.3 功能完整性清单**：34 项 P0 二元判定（通过/不通过），不通过则对应维度直接判 0 分
> - 强化 **7.4 发布门禁**：8 条必达条件 + 一票否决规则
> - 引入**完成度计算公式**：各维度得分 = 子指标通过率 × 权重；总分 ≥ 70% 方可发布
> - 所有指标均标注"测试数据规格"和"采样方法"，工程团队可复现、可自测
>
> **v3 变更说明（技术经理反馈后）：**
> - 新增 **Skill 系统**（市场独立品类，P1）、**Output Style / AI 风格切换**（P1）、**文件上传 + OCR 对话**（P0）
> - 新增第五类用户画像：**Skill 贡献者**
> - 调整 **AI 响应时间指标**：拆分为"首 token ≤3s + 完整结果 ≤8s"
> - 调整 **AI 推荐策略**：P1 为规则推荐（最常用/同分类），P2 为机器学习推荐
> - 明确 **插件分发两条路径的关系**：市场安装 = 文件系统放置的自动化包装
> - 补充 **长对话稳定性**验收标准（≥20 轮）
> - 明确"低端设备轻量模式"定义为 AI 不可用时的纯手动降级
> - 纳入 **命令面板**（P2）、**思维导图 & LaTeX 渲染**（P2）
> - 补充 barrel 导出、应用自动更新复用、设计常量等备注
>
> **v2 变更说明：** 基于已实现的基建能力（AI Agent 对话、五维插件模型、声明式 UI、平台数据管线、设计 Token 矩阵、运行时权限门控、跨会话记忆、平台 OCR 等），将产品上限从"人操作工具的单层平台"拔高到"人操作工具 + AI 调度工具的双层平台"。原有工作台、市场、插件详情、设置、通知中心等页面骨架全部保留——AI 层是叠加，不是替代。

## 一、产品定位与一句话价值主张

**Evergreen Base** 是一个**无账号、无服务端、本地优先、AI 原生的去中心化微工具集成平台**。大学生既可以在应用中一键安装课表、成绩、时间管理等微工具插件手动操作，也可以直接对 AI 说"帮我查明天课表"，AI 自动路由到对应插件并返回结果。插件从静态网站（如 GitHub Pages）直接拉取，无需注册登录，即装即用。

**核心差异点：**
- **双层交互：** "人手操作"与"AI 调度"共存——想自己点就自己点，想省事就说话，各取所需
- **零注册 / 零云端数据库** → 隐私天然安全，数据完全由用户掌握，AI 也在本地推理
- **插件分发依赖静态站点**（GitHub Pages 等）→ 去中心化、零服务器成本
- **热加载即装即用** → 不重启宿主，体验流畅
- **五维能力组合** → 一个插件可以是纯 AI 工具、纯 UI 模块、纯数据源、纯主题、纯设置项、纯 Skill，或任意组合。用户按需安装能力维度，不必须装全量包
- **声明即应用** → 插件只需声明"我是什么类型的数据、用什么 UI 范式展示"，渲染层自动生成界面；不同渲染器（Flutter / Web / CLI）各自实现同一份声明，一次声明多端运行

## 二、目标用户画像

### 2.1 主要用户：在校大学生（18–25 岁）

| 属性 | 描述 |
|------|------|
| **典型场景** | 查课表、查成绩、番茄钟计时、DDL 提醒、笔记便签、校园地图、拍照识别讲义、期末复习助手 |
| **设备** | Windows 笔记本（主力）+ Android 手机（移动场景），部分用 macOS / iOS |
| **技术能力** | 多数非技术背景，能使用应用商店式操作；对 AI 助手有基本认知（用过 ChatGPT 等），接受"对 AI 说话来完成任务"的交互方式 |
| **痛点** | 工具分散在多个 App/网页/命令行，频繁切换；部分工具需注册账号，隐私顾虑；想快速得到一个结果（"明天第一节课是什么"）但不想打开插件翻找 |
| **诉求** | 一个聚合入口，简单好用，隐私安全，免费；**最好有个 AI 帮我省掉点来点去的步骤** |

### 2.2 次要用户 A：学生开发者（有编程基础）

| 属性 | 描述 |
|------|------|
| **典型场景** | 写课表解析插件、校园网自动登录、成绩监控分享给同学 |
| **技术能力** | Dart/Flutter 或 Python 或任何可编译为 .exe 的语言 |
| **痛点** | 发布校园小工具需上架应用商店、搭建后端，门槛太高 |
| **诉求** | 低门槛开发 → 打包 → 分发，一个 PR 就让全校同学用上 |

### 2.3 次要用户 B：轻量贡献者（不会 Flutter，但会写脚本）

| 属性 | 描述 |
|------|------|
| **典型场景** | 写个 Python 爬虫查空教室、写个脚本解析教务处通知，填个 JSON 声明就能在 Evergreen 里跑 |
| **技术能力** | 会 Python / Node.js / 任何语言，不会 Dart/Flutter，不想学 UI |
| **痛点** | 有好用的脚本，但没法给非技术同学用——没有 GUI、没有分发渠道 |
| **诉求** | **只写后端逻辑 + 填一个 manifest.json，平台自动生成 UI**，门槛降到最低 |

### 2.4 次要用户 C：设计师 / 主题贡献者

| 属性 | 描述 |
|------|------|
| **典型场景** | 为 Evergreen 设计一套 Material You 风格主题 / iOS 风格主题 / 赛博朋克主题 |
| **技术能力** | 懂色彩体系、设计 token，不需要写代码 |
| **痛点** | 设计了一套好看的配色但没办法让其他人一键使用 |
| **诉求** | 填写 `theme.json` → 发布到主题市场 → 用户一键切换 |

### 2.5 次要用户 D：Skill 贡献者 🆕

| 属性 | 描述 |
|------|------|
| **典型场景** | 写一个"期末高数复习助手"让 AI 更懂如何帮你复习；写一个"托福口语 30 天计划"指导 AI 按日程陪练 |
| **技术能力** | 不会写代码，但擅长写提示词、设计学习路径、总结方法论 |
| **痛点** | 有好的学习方法论，但只能在自己和 AI 的一对一对话中使用，没法分享给同学 |
| **诉求** | **一个 Markdown 文件就能发布一个 AI 技能包**，门槛比写脚本更低——写提示词就能贡献 |

## 三、用户核心旅程

### 旅程 1：手动发现并安装插件（保留原有路径）

```
打开应用 → 进入"市场" → 浏览/搜索插件 → 点击卡片看详情
→ 点击"安装" → 进度条显示下载中 → 完成 → 自动出现在工作台 → 点开即用
```
**关键体验要求：** 从点击安装到可用 ≤ 5 秒；安装过程不阻塞其他操作。

### 旅程 2：AI 对话式任务执行（新增路径）

```
打开应用 → 点击 AI 入口（或快捷键唤起）→ 输入"帮我查明天课表"
→ AI 理解意图 → 自动调用课表插件的 Agent 工具 → 返回格式化结果
→ 用户追问"那下午有哪些课？"→ AI 基于上下文继续回答
→ AI 建议"要不要把课表插件固定到工作台？"→ 用户确认 → 一键固定
```
**关键体验要求：** AI 首 token 响应 ≤ 3s（流式反馈），简单查询完整结果 ≤ 8s；对话上下文连续；AI 可跨插件调度。

### 旅程 3：拍照即问（新增路径）🆕

```
用户拍了一张课表截图 → 打开 AI 对话 → 上传图片
→ AI 自动 OCR 识别截图内容 → 基于识别结果回答"明天有什么课"
→ 用户追问"第三节课在哪个教室？"→ AI 基于 OCR 内容继续回答
```
**关键体验要求：** 拍照到首条回答 ≤ 5 秒；OCR 识别准确率满足日常使用（中文 ≥ 90%）；云端不可用时自动降级本地 OCR。

### 旅程 4：安装 Skill 定制 AI 行为（新增路径）🆕

```
进入市场 → 筛选"Skill"品类 → 看到"期末高数复习助手"
→ 点击详情："让 AI 以苏格拉底式追问帮你复习高数，不会直接给答案"
→ 点击安装 → AI 对话中自动加载该 Skill → 用户说"帮我复习第一二章"
→ AI 切换到苏格拉底模式，逐步引导而非直接解答
```
**关键体验要求：** Skill 安装即生效，无需手动启用；Skill 可在设置中开关和切换。

### 旅程 5：对话发现 → 工作台沉淀（融合路径）

```
用户在 AI 对话中说"最近考试周压力大"→ AI 推荐"番茄钟"和"白噪音"插件
→ 用户点击推荐卡片 → 跳转插件详情 → 安装 → 自动出现在工作台
→ 用户后续直接在工作台点击使用，不必每次对话
```
**关键体验要求：** 从推荐到安装 ≤ 2 步；安装后无缝沉淀到工作台。

### 旅程 6：日常使用（双入口共存）

```
方式 A（手动）：打开应用 → 工作台 → 点击课表插件 → 查看今日课程
方式 B（对话）：打开应用 → AI 输入"今天有什么课" → 直接看到结果
```
**关键体验要求：** 两种方式结果一致、数据同源；用户无需选择，随时切换。

### 旅程 7：管理插件与偏好

```
进入"我的插件" → 查看已安装列表（按能力维度分组：Agent 工具 / UI 模块 / 数据源 / 主题 / 设置 / Skill）
→ 对特定插件：卸载 / 调整权限 / 固定到侧栏 / 管理 AI 记忆
→ 进入"设置" → 切换 AI 风格（解释型 / 学习型 / 简洁型 / 苏格拉底式）→ 管理插件源 → 导入/导出配置（含 AI 记忆）→ 切换主题
```
**关键体验要求：** 所有配置仅存本地；导入/导出包含 AI 对你的认知；换设备无缝衔接。

### 旅程 8：轻量开发者发布插件

```
写一个 Python 脚本查空教室 → 填写 manifest.json（声明名称、权限、数据格式、UI 范式）
→ evg build → 生成 .plugin → Fork 官方仓库 → 放入 static/ → 提 PR
→ CI 自动校验 → 合并 → 自动部署 → 清单更新 → 全校同学可用
```
**关键体验要求：** 不需要写 Dart/Flutter 代码；manifest 有清晰模板和校验。

### 旅程 9：Skill 贡献者发布技能包（新增路径）🆕

```
写一个 Markdown 文件（提示词模板 + 行为定义 + 适用场景描述）
→ 放入官方仓库 skills/ 目录 → 提 PR → 合并 → 出现在 Skill 市场
```
**关键体验要求：** 一个 Markdown 文件即可发布；不需要任何编程知识。

### 旅程 10：设计师发布主题

```
参考官方 theme.json 模板 → 定义语义 token + 组件 token
→ 打包 → 提交到官方仓库 themes/ 目录 → PR → 合并 → 出现在主题市场
```
**关键体验要求：** 填 JSON 即可；本地可预览；发布后一键切换。

## 四、功能需求详情

### 4.1 插件市场（静态源）

**P0（MVP 必备）：**
- 应用内置默认官方源 URL（GitHub Pages），首次启动自动加载插件清单
- 市场页以瀑布流卡片展示插件：**名称、简介、图标、分类标签、能力标签（Agent / UI / 数据 / 主题 / 设置 / Skill）**
- 支持按**能力维度**筛选："只看 Agent 工具"、"只看数据源"、"只看主题"、"只看 Skill"
- 点击卡片进入详情页：完整描述、版本号、截图轮播、**权限声明列表（分级展示）**、**能力维度清单**、开发者信息、安装按钮
- 搜索：按插件名称和描述关键字模糊匹配
- 分类筛选：横向标签栏（"学习""生活""效率""工具"）+ 能力维度标签
- 安装按钮：点击 → 显示下载进度 → 完成后自动变为"已安装"状态
- 下拉刷新重新拉取清单，对比版本号，已装插件有更新时显示"更新"角标

**P1（增强）：**
- 用户可手动添加/删除自定义静态源 URL
- 多源管理界面：源名称、URL、状态、最后同步时间
- 详情页展示更多元数据：兼容 OS 列表、依赖 SDK 版本
- "仅显示兼容当前设备"过滤开关
- **规则推荐：** 基于使用频率和分类的简单推荐（"你最常用的 3 个插件"、"同分类热门"），纯本地计算

**P2（未来）：**
- 评分与评论（基于 GitHub Issues 的轻量方案）
- 插件使用统计（匿名、默认关闭）
- **机器学习推荐：** 基于使用习惯的个性化推荐算法

### 4.2 热加载机制

**P0（MVP 必备）：**
- 安装：从静态源下载 `.plugin` 包 → 校验签名 → 解压到本地插件目录 → 注册到宿主 → 立即可用，**全程不重启宿主**
- **市场安装 = 文件系统放置的自动化包装：** 市场下载 `.plugin` → 解压到 `plugins/<name>/` 目录 → 热加载注册，与手动放置插件目录等效。两条路径共存——开发者本地调试时手动放置，普通用户通过市场一键安装
- **五种能力类型 + Skill 各自独立热加载**——Agent 工具、UI 模块、数据源、主题、设置项、Skill 各自独立注册和卸载，互不阻塞
- 卸载：移除插件文件 → 注销注册 → 从工作台消失，**不遗留残留文件**
- 更新：检测新版本 → 下载新版 → 替换旧版 → 保留用户配置和 AI 记忆
- **插件更新检测可复用宿主自动更新机制**（UpdateService 已对接 GitHub Release API），底层 HTTP 下载 + 版本比较逻辑共享

**P1（增强）：**
- 下载失败自动重试 3 次（间隔 1s/3s/5s），仍失败则明确提示并提供手动重试
- 安装/卸载 toast 通知不打断当前操作
- 下载支持断点续传

### 4.3 本地管理与偏好

**P0（MVP 必备）：**
- "我的插件"页面：已安装插件列表，展示名称、图标、版本、占用空间、**能力维度标签**
- 列表支持按**能力维度分组**查看（"我的 Agent 工具" / "我的 UI 模块" / "我的数据源" / "我的主题" / "我的设置项" / "我的 Skill"）
- 排序（按名称 / 安装时间 / 最近使用）
- 卸载：确认弹窗 → 删除；**支持按能力维度部分卸载**（只卸载 UI 保留 Agent 工具）
- 所有配置仅存本地，数据持久化于统一的 `.greenix/` 目录体系

**P1（增强）：**
- 导入/导出配置：导出为 `.evgconfig` 文件（含已装插件列表、源地址、偏好设置、**AI 记忆数据**）；导入时自动从源重新下载插件并恢复 AI 认知
- 插件分组归类（用户自定义文件夹/标签）
- 本地使用统计

### 4.4 AI Agent 对话层

> **设计原则：** AI 层是体验加速器，不是替代品。工作台、市场、插件详情等手动操作路径完全不改动——AI 入口是在这些之上多加一条更快的路径。用户自己选走哪条。

**P0（MVP 必备）：**
- 全局 AI 入口：侧栏固定 AI 图标、快捷键唤起（如 `Ctrl+Space`）、工作台顶部搜索框可切换为 AI 对话
- 自然语言理解：用户输入"帮我查明天课表"→ AI 识别意图 → 自动查找并调用对应插件的 Agent 工具 → 返回格式化结果
- **跨插件调度：** AI 可在一个对话中调用多个插件——"查课表 + 番茄钟记录，分析我的学习时长分布"
- 对话界面：聊天气泡式，支持 Markdown 渲染结果、思维导图、LaTeX 公式；可折叠的工具调用过程（"AI 正在使用课表插件…"）；**流式输出（首 token ≤3s），用户即时感知 AI 在工作**
- 上下文连续：追问不需要重复说明（"那后天呢？"→ AI 理解为"后天的课表"）；**底层自动上下文压缩（Context Compaction）保障长对话不"失忆"**，用户无需感知
- **文件上传 + OCR 对话：** 🆕 支持在对话中直接上传图片/PDF → AI 自动 OCR 识别内容 → 基于识别结果回答（"拍照课表 → 问明天有什么课"）
- 对话历史：可搜索、可删除

**P1（增强）：**
- **对话发现 → 工作台沉淀闭环：** AI 推荐插件 → 一键查看详情 → 安装 → 自动固定到工作台或侧栏
- AI 可主动推送（基于通知权限）："明天课表有变动，教室改到 B201"
- 对话中引用插件结果可一键跳转到插件 UI（"在课表插件中查看完整周表"）
- AI 工具调用的运行时权限门控：AI 调用敏感工具时弹出确认（"AI 需要读取你的文件来查成绩截图，允许吗？"）
- **Skill 市场：** 🆕 市场新增 Skill 品类——用户可安装 AI 技能包（提示词模板 + 行为定义），让 AI 获得领域特化能力（如"期末高数复习助手"、"托福口语 30 天陪练"、"雅思写作批改"）。Skill 是最轻量的贡献方式——一个 Markdown 文件即可发布
- **AI 风格切换：** 🆕 用户可在设置中选择 AI 对话风格——**解释型**（边做边解释原理）、**学习型**（协作模式，留 TODO 让学生自己完成）、**简洁型**（最少文字输出）、**苏格拉底式**（只追问不直接给答案）。面向教育场景的差异化功能，对大学生群体有独特吸引力

**P2（未来）：**
- 语音输入
- 多轮复杂任务编排（"帮我把这学期的课表导出为 ICS 文件并设置提前 15 分钟提醒"）
- 本地模型支持（完全离线 AI）
- **命令面板：** 🆕 类似 VS Code 的 Ctrl+Shift+P——搜索并快速执行 AI 查询或插件操作（"固定番茄钟到侧栏"、"卸载课表 UI"）

### 4.5 多维插件模型

> **设计原则：** `.plugin` 包作为面向普通用户的"一键安装"格式保持不变。底层引入五种正交能力维度 + Skill，支持更灵活的"能力组合式安装"。两种模型共存，用户不需要理解底层维度也能正常使用。

**六种能力维度：** 🆕（新增 Skill）

| 能力维度 | 用户可见描述 | 示例 |
|----------|------------|------|
| **Agent 工具** | "让 AI 能帮你做某事" | 查课表、查成绩、设置提醒 |
| **UI 模块** | "一个可以打开使用的界面" | 课表周视图、成绩趋势图、番茄钟计时器 |
| **数据源** | "提供数据给其他插件共享" | 教务系统课表数据、校园网登录状态 |
| **主题** | "一套配色和视觉风格" | 深色模式、Material You、赛博朋克 |
| **设置项** | "一组可调节的偏好" | 课表显示周数、番茄钟时长 |
| **Skill** 🆕 | "一套 AI 行为模式" | 期末复习助手、雅思口语陪练、苏格拉底追问 |

**P0（MVP 必备）：**
- 插件清单声明能力维度：每个插件在 manifest 中声明自己提供了哪些维度的能力
- 安装时自动发现所有维度并注册
- 市场中展示能力标签（六种颜色区分）

**P1（增强）：**
- **能力组合式安装：** 用户可选择"只安装这个插件的 Agent 工具，不安装 UI"——适合只想用 AI 调度的用户
- 跨插件数据复用：课表数据源同时被"课表 UI 插件"和"DDL 提醒插件"消费，无需重复拉取

### 4.6 平台级数据管线

**P0（MVP 必备）：**
- 数据源作为一等公民：插件可声明自己提供的数据类型（如"课表""成绩""课程"）
- 数据注册表：平台统一记录所有可用数据源及其状态

**P1（增强）：**
- 缓存策略：数据源声明缓存策略（缓存优先 → 过期刷新 → 强制刷新），平台统一执行
- 源状态可视化：用户可在数据源详情中看到数据新鲜度（"最后更新：2 分钟前"）、连通状态
- 跨插件数据复用：多个 UI 插件可消费同一个数据源，数据只拉取一次

### 4.7 主题市场

**P0（MVP 必备）：**
- 内置深色/浅色主题切换（默认跟随系统）
- 第三方插件 UI 自动继承宿主主题配色（语义 token → 组件 token 映射）
- 设计系统已覆盖**像素级组件规范**：聊天气泡圆角（16px）、电子表格单元格（100×24px）、幻灯片宽高比（16:9）、编辑器行高（19.5px）、仪表盘响应式断点（4/3/2 列）、命令面板宽度（500px）等——声明式 UI 不只是"能用"，而是"精装"

**P1（增强）：**
- 主题作为独立插件品类出现在市场中，可浏览、安装、一键切换
- 主题预览：安装前可预览主题在典型页面中的效果
- 社区贡献主题通过 PR 提交到官方源 `themes/` 目录

**P2（未来）：**
- 用户自定义主题编辑器（可视化调色 + 实时预览）
- 主题定时切换（日间浅色 / 夜间深色）

### 4.8 声明式 UI 范式

> **设计原则：** 声明式 UI 是**低代码补充路径**，不替代自定义 UI。有 Flutter 能力的开发者仍然可以写完全自定义的 Dart UI；不会 Flutter 的轻量开发者用声明式即可让后端脚本拥有前端界面。两条路径共存。

**P1（增强）：**
- 预定义 UI 范式：**表格（spreadsheet）、卡片列表（default）、对话（chat）、文档（document）、仪表盘（dashboard）、演示（presentation）、编辑器（editor）** — 共 7 种
- 插件在 manifest 中声明选用哪种范式 + 数据字段映射 → 渲染层自动生成 UI
- 开发者只需提供后端逻辑（Python 脚本 / .exe）+ manifest.json，**不需要写 Dart/Flutter**
- 每种范式有**精确的像素级渲染规则**（组件尺寸、间距、断点），确保自动生成的 UI 品质一致

**P2（未来）：**
- 范式可组合（"卡片列表 + 顶部仪表盘"）
- 社区贡献自定义范式模板

### 4.9 平台级感知服务

**P1（增强）：**
- **OCR 文字识别：** 平台一级服务，插件通过统一 API 调用（无需各自对接 OCR）
  - 典型场景：课表插件拍照导入、笔记插件扫描讲义、成绩插件识别截图
  - 云端 + 本地两级自动降级，无网络时使用本地引擎
  - **与 AI 对话深度整合：** 用户在对话中上传图片 → 自动 OCR → AI 基于识别结果回答（P0 已覆盖）

**P2（未来）：**
- 语音识别（语音输入 → AI 处理 → 执行）
- 图像分类（拍照识别校园建筑、植物等）
- 所有感知服务对全部插件开放，无需插件各自集成

### 4.10 跨会话 AI 记忆

**P1（增强）：**
- AI 从对话中自动提取用户特质（"大二计算机系"、"喜欢深色模式"、"周三下午没课"）并持久化
- 三层 Scope：用户级（跨插件）、项目级（某个插件的上下文）、会话级（当前对话临时）
- 用户可查看、编辑、删除所有 AI 记忆
- **换设备导入记忆：** 导出 `.evgconfig` 时包含 AI 记忆 → 新设备导入 → AI 无需重新了解你
- **越用越懂你：** 新安装的课表插件自动知道你是大二计算机系 → 默认展示对应课表

### 4.11 工作台与快捷入口

**P0（MVP 必备）：**
- 工作台默认展示全部已安装插件的卡片网格
- 点击插件卡片 → 打开插件运行界面（声明式 UI 自动渲染 或 自定义 Dart UI）
- 侧栏顶部区域：用户可将插件"固定"到此，作为常驻快速入口
- **AI 入口常驻侧栏**，与工作台、市场等并列

**P1（增强）：**
- 工作台卡片可拖拽重排序
- 工作台支持布局切换：网格 / 列表
- "最近使用"行：展示最近 5 个打开过的插件（含通过 AI 调用的插件）
- 侧栏固定区支持拖拽排序
- 插件浮层支持最小化（悬浮球）、最大化、关闭
- 分屏：同时运行两个插件各占一半区域
- **智能固定建议：** AI 根据使用频率建议"要不要把课表固定到侧栏？"

**P2（未来）：**
- 智能推荐（纯本地，P1 为规则推荐，P2 为 ML 推荐）
- 工作台自定义壁纸/布局密度
- **命令面板（Ctrl+K）：** 🆕 搜索并快速执行 AI 查询或插件操作

### 4.12 通知系统

**P0（MVP 必备）：**
- 插件可通过统一通知 API 发送本地通知
- 用户在安装时授予通知权限

**P1（增强）：**
- 通知中心面板：展示所有历史通知，标注来源插件

**P1（增强）：**
- CLI `evergreen-cli`：`init`（生成模板，含纯 Python + manifest 模板和 Dart 完整模板两种）、`build`、`validate`、`dev`

## 六、非功能需求（产品视角）

### 6.1 性能体验指标

| 指标 | 目标值 | 用户感知 |
|------|--------|----------|
| 插件下载+热加载总耗时 | ≤ 5 秒（4G/WiFi 常态） | "点了安装马上就能用" |
| 热加载本身（不含下载，含声明式 UI 首帧） | ≤ 2 秒 | 安装到可用的切换几乎无感 |
| 宿主冷启动 | ≤ 3 秒 | "打开就绪" |
| 市场清单首次加载 | ≤ 2 秒 | 首屏卡片快速展示 |
| **AI 首 token 响应** 🆕（调整） | **≤ 3 秒**（流式反馈，用户感知 AI 在工作） | "打字还没停 AI 就开始回了" |
| **AI 简单查询完整结果** 🆕（调整） | **≤ 8 秒**（含 tool calling 往返） | "说完话等一下就有结果" |
| AI 跨插件复杂查询 | ≤ 12 秒 | "等一下也值" |
| 图片上传 + OCR + 首 token | ≤ 5 秒 | "拍照马上就识别出来了" |
| 单个插件运行时内存 | ≤ 50MB | 不拖慢系统 |
| 平台级数据缓存新鲜度 | 按策略自动刷新 | "数据总是最新的" |

> **关于 AI 响应时间的说明：** 以上指标取决于 LLM API 延迟，非平台自身性能所能完全控制。"首 token ≤3s"确保流式反馈让用户即时感知 AI 在工作，"完整结果 ≤8s"覆盖典型 tool calling 往返。实际体验可能因模型和网络条件波动，指标作为优化方向而非硬性门禁。

### 6.2 安全性（用户视角）

| 层级 | 用户可见的安全机制 |
|------|-------------------|
| **安装前** | 详情页展示权限列表，敏感权限橙色警告，用户知情决定 |
| **安装时** | 逐项授权弹窗（通俗语言说明每项权限的用途） |
| **手动使用中** | 插件运行于隔离沙箱，无法访问其他插件数据 |
| **AI 调度时** | **四级运行时权限门控**——AI 调用敏感工具时实时弹出确认（"AI 需要读取文件来查成绩截图，允许吗？"），用户可选：总是允许 / 本次允许 / 拒绝 / 本次拒绝。与安装时授权互补——前者建立信任基线，后者在 AI 自主行为场景提供实时监督 |
| **管理中** | 随时在权限管理中开关任意权限、查看权限使用历史 |
| **分发** | 所有插件包数字签名 + 完整性校验；源强制 HTTPS |
| **崩溃** | 单个插件崩溃不影响宿主，弹出提示并提供禁用/反馈入口 |

### 6.3 可靠性

- 下载中断自动重试 3 次
- 插件崩溃：捕获 → 提示 → 标记"不稳定"→ 连续 3 次自动禁用
- 源不可达：提示但不影响已装插件
- 配置/AI 记忆损坏：自动回退默认配置
- **AI 服务不可用：** 降级为纯手动模式，工作台和市场正常使用，AI 入口灰色置灰并标注"AI 暂不可用"
- **OCR 云端不可用：** 自动降级到本地 OCR 引擎

### 6.4 兼容性

- 优先保证 **Windows（Win10+）** 和 **Android（Android 8+）** 完整体验
- macOS 和 iOS 同步支持
- **低端设备策略** 🆕（调整）：4GB RAM 以下设备自动关闭非必要动效；AI 功能正常提供（本身不消耗本地算力），不提供"缩水版 AI"——AI 要么完整可用，要么因网络/服务原因降级为纯手动模式。缩水的 AI 体验可能比没有 AI 更差
- **双轨架构下的多端扩展：** 同一份模块声明可由不同渲染器实现（Flutter / Web / CLI），未来加平台只需写新渲染器，不改插件

### 7.2 各维度详细量化标准

#### D1：安装闭环（权重 12%）

| 子指标 | MVP 阈值 | V1.0 目标 | 测试数据规格 | 采样方法 |
|--------|----------|----------|-------------|---------|
| 安装成功率 | ≥ 90% | ≥ 95% | 6 种类型 × 各 20 次 = 120 次安装 | 统计 `成功次数 / 120`；失败 = 任一步骤(下载/校验/解压/注册)报错 |
| 安装耗时 P50 | ≤ 5s | ≤ 3s | 同上 120 次样本 | 从点击"安装"到按钮变为"已安装"的 wall-clock 时间 |
| 安装耗时 P95 | ≤ 8s | ≤ 5s | 同上 | — |
| 安装耗时 P99 | ≤ 12s | ≤ 8s | 同上 | 超过 15s 视为超时失败 |
| 安装不阻塞 UI | 120 次中 0 次 UI 冻结 > 500ms | 同 MVP | 监控主线程帧率：安装期间无一帧 > 500ms | UI 冻结 > 500ms = 用户可感知的卡顿 |
| 进度条准确性 | 进度值单调递增，最终 = 100%，无跳跃/卡死 | 同 MVP | 120 次安装观察进度条行为 | 跳跃 = 从 20% 跳到 80%；卡死 = 同一数值停留 > 3s |

**测试环境：** 网络下行 10Mbps / 上行 2Mbps / 延迟 50ms（模拟典型校园 4G/WiFi）。插件包大小：Agent 工具 ~2MB / UI 模块 ~5MB / 数据源 ~1MB / 主题 ~0.5MB / 设置 ~0.1MB / Skill ~0.05MB。

## 十、关键风险与缓解

| 风险 | 影响 | 缓解策略 |
|------|------|----------|
| 静态源被墙/不稳定 | 国内用户无法加载市场 | 多源切换 + 国内镜像源（Gitee Pages）+ 内置备用源列表 |
| 插件质量参差不齐 | 体验差、安全风险 | CI 校验 + 人工审核 + 崩溃自动禁用 + 用户反馈 |
| AI 响应质量差 | 用户失去信任 | 限定 AI 可调用的工具范围、结果标注来源插件、提供手动操作作为降级路径 |
| AI 权限过度 | 用户隐私顾虑 | 四级运行时门控 + 敏感操作实时确认 + 权限使用历史可视化 + AI 记忆可管理 |
| **AI 依赖外部 API 延迟不可控** 🆕 | 响应时间超预期 | 评估指标拆分为"首 token ≤3s + 完整 ≤8s"；流式输出让用户即时感知进度；发布门禁中标注"取决于模型响应速度" |
| **Skill 内容质量** 🆕 | 低质量提示词泛滥 | Skill 审核流程（CI 自动检查格式 + 人工审核内容）+ 用户评分反馈 |
| 热加载低端设备性能不足 | 卡顿流失 | 自动降级 + 懒加载 |
| 生态冷启动（没插件/没主题/没 Skill） | 用户来了没东西 | MVP 内置 3 个官方模块（AI 助手/设置版面/插件商城）+ ≥2 套主题 + ≥2 个官方 Skill（如"苏格拉底复习助手"、"番茄钟专注模式"） |
| 声明式 UI 覆盖不足 | 复杂插件仍需 Dart | 自定义 Dart UI 路径保留作为补充，声明式覆盖 80% 常见场景 |
| 轻量开发者路径门槛仍高 | 没人用低代码路径 | manifest 模板 + 交互式 CLI 引导 + 示例覆盖典型场景；Skill 路径门槛更低（Markdown），作为入门贡献方式 |
| 多渲染器维护成本 | 跨平台品质不一致 | 核心渲染器（Flutter）优先保证品质，Web/CLI 作为实验性支持 |

> 📋 **v3 核心思路回顾：** 
> - "人手操作"的产品骨架（工作台、市场、插件详情、设置、通知中心）不改变——这些是产品的"地基"。
> - AI 层是叠加——用户自己点也行，对 AI 说也行，拍照问也行，各取所需。
> - v3 新增的 Skill 系统、AI 风格切换、文件上传+OCR 对话都是已跑通的基建，产品规划只需将它们编排到合适的位置——**基建已经跑在前面，产品规划站得更高，但脚踩实了**。
> - 三条贡献路径覆盖全光谱：Skill（Markdown，零编程）< 声明式插件（脚本+JSON）< 自定义插件（Dart 完整控制），任何人都有适合自己的贡献方式。

> 📋 **下一步建议：** 进入交互原型设计阶段。重点设计：① AI 对话与手动操作页面的平滑切换；② 六种能力维度在市场和已装管理中的呈现；③ Skill 市场的浏览和安装体验；④ AI 风格切换在对话中的即时体现；⑤ 文件上传的拖拽/粘贴/拍照入口。
