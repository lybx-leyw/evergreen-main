## 三、关键经验（踩坑记录）

1. **嵌套子包双轨架构**：lib/core/**、lib/renderer/** 是带独立 pubspec + stub 的嵌套包。
   根上下文 analyze 必然产生级联假错误（25,577 条中 ~2.4 万条）→ 根 analysis_options 排除 +
   子包内独立 analyze/test。**子包文件的任何改动必须以 flutter test 编译为准**（dart fix 曾误删
   errors.dart 12 处参数、expose_state_writer import，analyze 看不见、编译才暴露）。
2. **dart fix 误伤**：对嵌套包内文件自动修复有风险，应用后必须跑测试编译。
3. **测试陈旧引用**：模块迁移（scraper/classroom/zdbk → 新目录）后测试未同步，
   修复 import 后测试首次真正运行，暴露 28 个既有渲染层/数据依赖失败。
4. **git stash 实验教训**：HEAD 远落后于工作区时基线对比无效；且工作区大量未提交改动
   有丢失风险 → 已全部 commit（165330b）。
5. **PowerShell 转义地狱**：内联正则反复踩坑，复杂统计一律写脚本文件（.ps1/.py）执行。
