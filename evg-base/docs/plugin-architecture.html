Evergreen 上 · 中 · 下 插件架构图

上游 core/（声明与运行内核） → 中游 plugins/（manifest 声明 + 冷/热加载） → 下游 renderer/（渲染 / HTML 输出） · 本图基于 evg-base 代码实况绘制
上 · Core 核心 中 · Plugins 声明 下 · Renderer / HTML 冷插件：编译期静态绑定 热插件：运行时下载/重载
上 Core —— 核心引擎 / 运行内核（lib/core/） 统一出口：lib/evergreen_base.dart（barrel）
core/module/ 模块声明系统ModuleDescriptor（V2 树：模块→页面→布局→插槽→组件）
ModuleRegistry 注册/seal/搜索/导航
ModuleLoader 扫描 manifest 并启动后端进程
ModuleLifecycle 安装/卸载/禁用/启用/升级
ProcessManager 进程生命周期
core/plugin/ 插件执行抽象PluginRunner 接口：runOnce/startLong
SubprocessRunner（桌面 .exe / .py）
ChaquopyRunner（安卓进程内 Python）
core/services/ 服务层PluginInstaller .plugin 下载/签名/解压
UpdateService 版本检查
OCR 管线 / CoreHttpServer / 翻译队列
core/data/ 数据编排DataOrchestrator、Provider
缓存 / Diff / 数据源 HTTP Server
core/agent/ Agent 运行时Agent、Tools、Memory、Skills、Sessions
core/config/ 配置与权限Config、Settings、Permissions、Sources
core/theme/ 主题声明ThemeDescriptor、ThemeLoader、ThemeStore、渲染规则
core/utils/ 基础设施path_sandbox、greenix_path、python_env、file_utils
应用装配app_bootstrap.dart 组装注册中心
providers.dart Riverpod 全局提供者
generated/plugin_imports.g.dart 编译期导入
▼① 上 → 中：Core 扫描/安装插件声明，把 manifest 解析进 ModuleRegistry
中 Plugins —— 声明与注册（manifest.json 驱动） plugins/ 目录 + lib/core/module/builtins/ 内置模块，同一份声明格式
ModuleDescriptorV2 树形声明：模块→页面→布局→插槽→组件
样式/事件/数据绑定/数据源/进程等子描述符
PluginManifest轻量搜索模型（I10）
id/name/icon/维度/分类/版本
ProcessDescriptor后端进程声明：id/scope/autoStart/autoRestart/exe/runtime
DataSource / Event / Binding数据源、事件与绑定声明
冷插件 COLD编译期静态绑定 / 启动时批量注册
lib/generated/plugin_imports.g.dart 静态导入→内置模块 builtins/→scanAndLoadModules(plugins/)→registry.register + seal
表现：随宿主一起构建发布，稳定核心能力（Markdown、主题、设置等）；启动后即出现在侧边栏/命令面板。
热插件 HOT运行时下载 / 安装 / 重载（无需重启宿主）
下载 .plugin(ZIP)→SHA-256 签名校验→解压到 plugins/<id>/→ModuleRegistry.reloadModule()→渲染层重读声明
表现：插件设计器“安装/热重载”（A-P3）、PluginInstaller、ModuleLifecycle 的 enable/disable/upgrade。
注册与加载管道ModuleRegistry：register → seal → 依赖校验 → 路由/导航/命令面板
ModuleLoader：扫描 manifest → 启动后端进程（.exe/.py）→ 端口检测 + /health
PluginRunner：runOnce 短任务 / startLong 长驻进程
plugins/ 实际插件（13 个）ai-assistant · data-dashboard · dsh · html-creator · marketplace · pdf_translate · python-runner · scraper · settings · skill-creator · theme-creator · view · warm_study
▼② 中 → 下：ModuleRegistry 生成路由/导航 → 渲染层消费 ModuleDescriptor 树并输出 HTML
下 Renderer —— 渲染 / HTML 输出（lib/renderer/） 五层渲染架构 · Dart 渲染为可交互页面/HTML
app/ App 层顶层壳、全局主题服务
module/ 模块层ModuleDispatch、ModulePage
page/ 页面层CompositeView、布局引擎、独立页面
slot/ Slot 层SlotDispatch、SlotScale
components/ 组件层43 具名组件 + 20 占位
7 功能域：shared / document / data / interaction / creative / learning / controls
HTML / Dart 产物docs/index.html、plugin_guide.html、架构示意图.html、插件 render_log.html、r12_dart_render.png
数据回补（热反馈回路）渲染层用户交互 / 插件设计器修改声明 → 触发 reloadModule 或数据源请求 → 后端进程（PORT + /health，HTTP 数据源）→ 组件重新渲染。冷/热插件共用的同一批 manifest 字段在此最终落地为 HTML 页面。
本图所依据的代码实况（evg-base）： lib/evergreen_base.dart（barrel 双轨）、lib/core/module/（ModuleDescriptor 2860 行 V2 树 / ModuleRegistry / ModuleLoader / ModuleLifecycle / ProcessManager）、lib/core/plugin/plugin_runner.dart（SubprocessRunner / ChaquopyRunner）、lib/core/services/plugin_installer.dart、lib/core/docs/plugin-format.md（.plugin ZIP + SHA-256）、lib/generated/plugin_imports.g.dart（冷插件静态导入）、lib/renderer/renderer.dart（五层）、plugins/（13 个实际插件）。
