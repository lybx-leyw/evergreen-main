## 3. 命名规范

- 新文档一律 kebab-case 英文小写：`error-triage-guide.md`、`plugin-authoring-guide.md`
- 存量中文名文档（如 `愿景.md`）：**保留文件名**，只补文档头；迁移到英文名需用户逐个确认
- 目录：`docs/` 下按 `guides/`（指南）、`specs/`（规格）、`plans/`（规划）、`archive/`（归档）分类；子包文档留在各自 `docs/`
- `.history_docs/` 整体视为 `archive/`，只维护一份索引 README，不逐份改写

## 4. 文档头模板

每个正式文档第一段必须是元信息表：

```markdown
# 标题

| 元信息 | 值 |
| --- | --- |
| 状态 | draft / active / archived |
| 版本 | 0.1 |
| 日期 | YYYY-MM-DD |
| 负责人 | 角色或人名 |
| 适用 | 范围描述 |
```

- `状态` 三态必须显式声明；archived 文档可移入 `.history_docs/`
- 更新文档必须同步 bump `版本` 与 `日期`
- 本文件自身即为模板样例

## 5. 边界

- `.codebuddy/`、`.greenix/`、`plugins/` 内的文件是**代理运行时产物/用户数据**，不在规范化范围内，任何操作需单独确认
- `CLAUDE.md` 是 AI 代理指令文件：只统一文档头格式，**不改动指令内容**
- 根目录构建日志（build_*.log 等 ~50 个）：D7 归档或补 .gitignore，删除需用户逐个确认

## 6. 校验（D6 交付 tool/check_docs.dart）

- 抽查：docs/ 与子包 docs/ 下文档头合规率 → 目标 100%
- 命名抽查：新文件 kebab-case 比例 → 目标 100%（存量中文名豁免）
- 输出合规率报告供 D7 验收
