| 元信息 | 值 |
| --- | --- |
| 状态 | active（D2-D4 已落地，D7 验收） |
| 版本 | 1.0 |
| 日期 | 2026-07-25 |
| 负责人 | 全仓库工程师 |
| 适用 | lib/ 全部 Dart 代码 + test/ + tool/ |

## 1. 目标

**任何错误在日志里一条 grep 即可定位。** 排查路径只有一条：日志文件 → 按 errorId 检索 → 拿到模块、源码位置、错误消息、恢复提示。

## 2. 现状问题（基线 2026-07-25）

| 问题 | 证据 |
| --- | --- |
| 日志三轨并存 | `stderr.writeln`/`debugPrint` 遍布 ~90 个文件（main.dart 93 处），`Log()` 仅 ~30 个文件 —— release 模式 stderr 诊断丢失 |
| 静默吞错 | `catch (_) {}` 等高危模式在 ~150 个含 try/catch 的文件中出现 |
| 临时诊断残留 | main.dart 硬编码 `D:/evg-workplace/evg-base/build/first_error.txt`（注释自述"定位后删除"） |
| 临时构建标记 | `[BUILD-VERIFY]` 标签、ZJU-SAFETY 双打印（stderr+debugPrint） |

## 3. 铁律

1. **单一日志通道**：所有诊断信息必须走 `Log()`。`stderr`/`debugPrint` 仅允许作为 debug 模式的镜像输出（保留安卓 logcat 可见性），由 `Log` 内部实现，业务代码禁止直接调用。
2. **禁止静默吞错**：`catch (_) {}` 视为缺陷。catch 必须至少 `Log().warn(...)`；能恢复的场景用 `Result<T>` 承载失败，不能恢复的重新抛出或转 `AppError`。
3. **业务失败走 Result，异常走 AppError**：跨模块接口返回 `Result<T>`（[result.dart](lib/core/result.dart)），异常统一用 `AppError` 14 类工厂构造（[errors.dart](lib/core/errors.dart)），禁止裸 `throw Exception('...')` 跨模块传播。
4. **错误必须有 errorId**：每条 ERROR 日志必须携带 `errorId`（格式见 §4），用户反馈、日志检索均凭 errorId 关联。
5. **UI 展示用户可读消息**：`error.userMessage` 上屏，`error.debugMessage` + `source` 进日志，两者不得混用。

## 4. errorId 规范

```
EVG-<8位hex>                    // Log 层自动生成（D2 已落地）
EVG-<模块>-<8位hex>             // AppError 携带的增强格式（D3 落地）
```

| 前缀 | 模块 |
| --- | --- |
| BOOT | 启动序列（AppBootstrap） |
| CONF | config 子包 |
| DATA | data 子包 |
| MOD | module 子包 |
| AGT | agent 子包 |
| THM | theme 子包 |
| REND | renderer（渲染/布局/溢出） |
| SVC | services（OCR/翻译/安装/更新） |
| PLG | 插件运行时（Python/WebView 桥） |

生成（D2 已落地于 [log.dart](lib/core/log.dart)）：`sha256(模块|消息)` 前 8 位 hex，
由 `Log.error()` 自动生成；相同 (模块, 消息) 在去重窗口（10 分钟，`errorIdDedupeWindow`）
内复用同一 errorId，避免刷屏。模块信息在日志行 `[moduleTag]` 字段（如 `[PluginInstaller]`）。
`warn()/error()` 可显式传入 `errorId` 覆盖（AppError 在 D3 提供增强格式）。
日志行：`[2026-07-25 14:03:22.123] [ERROR] [PluginInstaller] [EVG-a1b2c3d4] 消息`

## 5. 日志行格式

```
[2026-07-25 14:03:22.123] [ERROR] [PluginInstaller] [EVG-SVC-a1b2c3d4] 消息体
  data: {...}
  error: <原始异常>
  stack: <调用栈>
  source: lib/core/services/plugin_installer.dart:123
```

- `moduleTag` 由调用栈提取（现有 `Log._extractModuleTag` 保留）
- `errorId` 优先取 `AppError.errorId`，否则取 `StackTrace` 哈希
- 溢出/渲染错误（`RenderError`）额外附带 widget 树摘要前 3 层

## 6. 排查标准流程

1. 找日志：Windows `%LOCALAPPDATA%/evergreen/logs/`，安卓 `logcat -s Flutter`，debug 模式 stderr
2. 检索：`dart run tool/log_scan.dart --id EVG-xxx` 或 `--module SVC --since 2026-07-25`（D7 交付）
3. 定位：`source` 字段给出文件:行号；`stack` 给出调用链
4. 上报：UI 错误中心一键导出最近 200 条（`Log.exportRecent` 已有）附 errorId

## 7. 验收标准（D7）

- [ ] main.dart 无裸 `stderr.writeln` 业务诊断
- [ ] 任一注入错误可在 3 分钟内凭 errorId 定位到文件:行号
- [ ] 静默 catch 数较基线下降（services/ 20 处专项清零）
- [ ] 错误中心可导出、可复制 errorId
