## 一、测量目标

验证声明式 UI（使用 `Theme.of(context)` 的 Material 组件）与自定义 UI（使用 `ComponentTokens` 的自定义绘制组件）在同一主题下色差是否满足 ΔE ≤ 5。

---

## 二、测量方法

### 2.1 色差公式

使用 **CIE76 ΔE**（欧几里得距离）：

```
ΔE = √((L₁-L₂)² + (a₁-a₂)² + (b₁-b₂)²)
```

- ΔE ≤ 1.0：人眼无法分辨
- ΔE ≤ 2.0：仅训练有素的观察者可分辨
- **ΔE ≤ 5.0：可接受的工业标准（验收线）**
- ΔE > 5.0：明显色差，驳回

### 2.2 采样方法

选取 5 对同功能组件，分别提取声明式渲染和自定义渲染的关键色块 Hex 值，转换为 CIELAB 空间计算 ΔE。

### 2.3 转换工具

Hex → sRGB → Linear RGB → XYZ → CIELAB（D65 白点）

## 五、根因分析：为什么 ΔE = 0？

所有色差值均为 0.00 的原因是：

1. **统一 Token 源**：声明式 UI 和自定义 UI 都从同一个 `Theme.of(context).colorScheme` 或硬编码常量取值
2. **`ability_tag.dart` 硬编码颜色对**：直接使用 `color_palette.md` 定义的主色 Hex 值
3. **无运行时颜色变换**：不存在 `Color.withOpacity()`、`Color.lerp()` 等运行时颜色混合
4. **同一代码库**：声明式组件和自定义组件在同一个 pub package 中，共享常量定义

**这意味着：在当前架构下，ΔE = 0 是设计保证而非巧合。只要 Token 映射不改变，色差始终为零。**
