# 二、探索深度 + 逆向增强计划（2026-08 新增 · 待实施）

> 背景（用户真实场景反馈）：
> 1. 复杂网站探索时 AI 只摸表面几个无效信息，没有按网站体量与用户需求做启发式深入探索；
> 2. `set_env_var` 写入凭据报 "Cannot modify unmodifiable map"，环境变量注入账号密码失败堵塞流程；
> 3. 逆向工具是否够强：需不需要更多请求日志捕获与 AI 页面操作。
>
> 根因结论（已完成代码勘察，2026-08）：
> - 探索深度不足 = **无启发式策略提示词 + 导航后无页面内容可读（AI"失明"）+ 20 页硬上限与
>   空转熔断共同诱导提前收尾 + 用户数据目标从不进入 AI 上下文 + 无噪音链接甄别指导** 五重叠加；
> - set_env_var bug = `ScraperEnvStore.load()` 在文件缺失/损坏时返回 `const {}`（不可变 map），
>   `setVar()` 在 try 块外 `all[k]=v` → 抛 "Cannot modify unmodifiable map"（**已修复，见 P0**）；
> - 逆向 = Windows CDP 引擎级抓包已不弱，但**信息完整性不足**（状态码/响应头/Set-Cookie/类型被丢弃）、
>   **AI 完全被动**（无点击/填表/滚动/任意 JS/POST）、双通道重复捕获与日志无上限。

## P0 — set_env_var unmodifiable map 修复 `[x]`（已实施）

**目标**：修复首次写入环境变量崩溃，凭证注入链路打通。

**改动**：
- `scraper_env.dart`：`load()` 全部返回**可变**空字典；`setVar()` 将 `all[k]=v` 移入 try，失败返回 `[error: ...]`。
- `agent/tools/scraper_tools.dart`：`SetEnvVarTool.execute` 加 try/catch 兜底。
- `test/scraper/scraper_env_test.dart`：新增 8 用例（首写回归/覆盖写/非法 key/损坏文件/镜像/合并/不回显）。

**验收**：`flutter test test/scraper/scraper_env_test.dart` 全过；探索模式首次 `set_env_var` 返回 ✅。

## P1-A — 用户需求注入 + 探索策略提示词 `[ ]`

**目标**：让 AI 知道"用户要什么数据"并按网站体量规划探索广度/深度，而不是扁平平扫。

**证据**：
- `scraper_ai_panel.dart:1562-1579` 探索任务 prompt 无 `dataScope`（只有步骤 + 锁定域名）；
- `explore_scope.dart:74-83` `dataScope` 只注入 Guardian（`scraper_ai_panel.dart:1539`），不进探索 Agent；
- `scraper_skill_const.dart:534-543` Step 1 只写"循环直到无新链接或触达上限"，无体量预估/层级下钻/链接甄别指导；
- `scraper_skill_const.dart:682-683`"少问问题"压制 AI 向用户索取目标。

**改动**：
- `scraper_ai_panel.dart` `startExplore`：`dataScope` 非空时注入任务 prompt（"用户数据目标: …，优先深挖相关栏目"）；为空时提示 AI 先用 `ask` 确认目标再开始深挖。
- `scraper_skill_const.dart` `scraperExploreSkillBody` 新增「探索策略启发式」章节：
  - **体量预估**：首页导航栏目数 / 是否分页 / 是否 SPA → 判断站点规模，规划探索预算；
  - **广度优先扫骨架，再按目标深度下钻**：目标栏目 > 列表/详情 API > 静态页；
  - **链接甄别**：`href="#"` / `javascript:` / 空文本 / 登录·注册·关于·隐私 → 噪音不导航；
    分页 / 列表 / 详情 / `/api/` / `.json` → 数据入口优先；
  - **导航后必须回读**：`list_captured_requests` + 页面快照（P1-C）判断页面类型再决定下一步；
  - 放宽"少问问题"：允许探索前 ask 用户目标数据。
- 探索 Skill 铁律 5（`scraper_skill_const.dart:447-448`）升级：由"至少 1 页"改为"摸清栏目骨架 + 目标栏目至少 1 条数据入口证据"。

**验收**：任务 prompt 含用户数据目标；AI 轨迹出现"先扫栏目骨架 → 下钻目标栏目"；不再把登录/关于页当候选数据源。

## P1-B — 探索守卫合理化 `[ ]`

**目标**：修正"分页烧光页数预算 / 请求上限语义失真 / 重访被熔断 / 归类门槛形同虚设"。

**证据**：
- `explore_workflow.dart:789-796` `_urlKey` 只去 fragment，query 不归一 → `?page=1/2/3` 各算一页；
- `explore_workflow.dart:745` `recordRequest()` 只在导航时调用 → "50 请求"实为"50 次导航"；
- `explore_workflow.dart:750-773` 空转熔断把"重访后二次探索"计为无产出；
- `explore_workflow.dart:217` `minPagesForCategorize=1`，导航 1 页即可归类。

**改动**：
- `_urlKey`：分页类 query 参数（`page/p/pn/pageNum`）归一（值→`{N}`）后参与去重，其余 query 保留；
- 请求上限语义：改为按 `captureWorkflow.logs` 真实捕获条数计数（或把 UI/AI 文案改为"导航次数"），消除误导；
- 空转熔断：区分"重访"（重复导航已访问页）与"二次探索"（重访后重新枚举链接/资源/读日志）——
  导航重访不直接计为无产出；对同一页"重新枚举资源/读日志"的动作不触发熔断；
- `minPagesForCategorize`：默认提至 3~5（或按站点规模：`maxPages` 越大门槛按比例越高）。

**验收**：`?page=1/2/3` 归一为 1 页；AI 看到的请求计数与日志条数一致；对已访问页二次枚举不触发熔断；
探索不足（<3 页无日志）时 `present_data_sources` 被拒并给明确指引。

## P1-D / P2-1 — AI 页面操作工具（点击/填表/滚动/提交）`[ ]`

**目标**：AI 能驱动真实用户流（点菜单、填表登录、滚动触发懒加载、翻页），触达"交互后才出现"的深层数据接口。

**验收**：对需登录/点击加载的站点，AI 可自主完成"进入目标栏目 → 触发数据请求 → 读日志归类"；操作被 scope 约束。
