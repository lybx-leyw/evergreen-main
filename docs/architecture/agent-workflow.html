② auto-workflow-skill
evergreen-auto-workflow
调研 → 评估（时效×可移植决策门）→ 改造/创作 → 双平台验证的自动化产线；被否项目记录原因立即舍弃。
③ 一支笔 + AI 产线
SKILL.md → 笔 → Agent
方法沉淀为「笔」，AI 握着它源源不断产出插件：纯 Python、双平台铁律、HTML 优先——插件沿传送带进入仓库。
♻️ 飞轮闭环：仓库中的插件被平台自动发现并集成到项目 → 使用反馈与经验回流 → 再次驱动 AI 创作新插件。装配线不是一次性流水，而是自我增强的循环。

② 平台端优化 → 队长 Agent → OWNER 一一派发

AGENT.md §6 索引
队长（root）只统筹、仲裁与索引维护；业务代码一律派发给对应 OWNER 在管辖目录内自主完成
📋 AGENT.md 边界红线：队长禁止直接改动任何子 OWNER 管辖目录内的业务代码（应派发）；绕过 OWNER 边界做跨模块改动同样禁止。跨 OWNER 契约变更（HTTP 端点、端口文件格式、ModuleDescriptor 字段等）必须召集相关 OWNER 对齐并登记（§5.1）。
