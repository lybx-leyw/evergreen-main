## 原理

### 1. 中游核心定位

中游是**声明层**——插件开发者不写 Dart UI 代码，只填写 JSON 声明文件，平台根据声明自动生成 UI。核心哲学："声明即应用"。

### 2. 插件的组成结构

```
plugins/<name>/
├── module/
│   ├── manifest.json        ← 模块声明（必填 type: "module"，schemaVersion: "2.0"）
│   └── <name>.exe            ← 后端进程（Python 打包或任意语言）
├── agent/
│   ├── manifest.json         ← Agent 工具声明（name/description/schema/argMode）
│   └── <name>.exe            ← 可执行文件
├── config/config.json        ← 设置项声明
├── theme/theme.json          ← 主题定义
├── data/manifest.json        ← 数据源声明
└── skill/*.md                ← Skill 定义文件
```

### 3. Manifest.json 驱动范式

Module 的 `manifest.json` 是整个中游的核心（V2 格式）：

```json
{
  "type": "module",
  "schemaVersion": "2.0",
  "id": "my-module",
  "name": "我的模块",
  "route": "/my-module",
  "renderMode": "dart",
  "process": [
    {
      "exe": "module/my-module.exe",
      "protocol": "http"
    }
  ],
  "pages": [
    {
      "id": "page1",
      "label": "页面一",
      "default": true,
      "layout": {
        "type": "grid",
        "preset": { "columns": 2, "gap": 12 },
        "slots": {
          "left": {
            "component": { "type": "chat", "config": { ... } }
          },
          "right": {
            "component": { "type": "data-table", "config": { ... } }
          }
        }
      }
    }
  ],
  "actionButtons": [
    {
      "id": "export_action",
      "label": "导出数据",
      "icon": "download",
      "process": {
        "exe": "module/export.exe",
        "protocol": "http"
      }
    }
  ]
}
```

关键变化（V1 → V2）：
- `process` 从单字符串变为 **对象数组** `[{exe, protocol}]`
- 布局 `type` 从 `"composite"` 变为具体布局类型（`grid`/`flex`/`fullscreen`/`absolute`/`dock`）
- 删除了 `descriptor.ui` 字段，改为按 pages/workspace 自动选择视图

### 4. 四级进程层级

.exe 与**组件**挂钩（不是与模块挂钩）：

| 层级 | manifest 路径 | 生命周期 |
|------|-------------|---------|
| ① 模块级 | `process[]` | 模块加载 → 卸载 |
| ② 页面级 | `pages[].globalProcess` | 页面激活 → 切走 |
| ③ 栏位/组件级 | `pages[].layout.slots.<key>.process` | 栏可见 → 隐藏 |
| ④ 动作级 | `actionButtons[].process` | 按钮触发 → 完成即退出 |

每个进程声明 `exe` 和 `protocol`（目前统一为 `"http"`）。

### 5. 标准 .exe 契约

所有层级的 .exe 遵循同一套契约（不限语言）：

1. 启动 `HTTPServer("127.0.0.1", 0)`（OS 分配随机端口）
2. stdout 首行 `PORT:xxxx`
3. core 捕获端口 → 后续全部走 HTTP JSON
4. 提供 `/health` 端点供 core 健康检查

模块级 .exe 通常还承担**聚合代理**角色——读取 `.agent_port`、`.data_port` 等端口文件发现上游服务，转发/聚合数据请求。

### 6. dataSource 数据绑定

除进程外，页面和组件可声明与进程生命周期**解耦**的数据源：

```json
"dataSource": {
  "endpoint": "/api/lottery/draw",
  "refreshInterval": 15,
  "dataPath": "history",
  "transform": "rarityToPie"
}
```

| 字段 | 作用 |
|------|------|
| `endpoint` | 请求路径 |
| `refreshInterval` | 自动刷新间隔（秒），0 = 不自动刷新 |
| `dataPath` | 从响应 JSON 提取数据的路径 |
| `transform` | 数据变形函数名 |

dataSource 可在页面级（整页共享）或组件级（单组件独立数据源）声明。

### 7. Agent 工具的三种 argMode

- **stdin**：JSON 写入 stdin → 读取 stdout
- **args (flag)**：`--key value` 格式
- **args (positional)**：按 order 顺序排列 value
- **args (json)**：`--args=<json>` 整体传递

### 8. V2 渲染模式

- `renderMode: "dart"` → Flutter Widget 渲染（`ModuleDispatch` → `CompositeView`/`EditorView`/`DefaultView`）
- `renderMode: "html"` → WebView 内嵌 HTML 渲染（`HtmlRenderView`）

## 效果

- **插件热加载**：放入 `plugins/` 目录即自动注册，无需重启宿主
- **语言无关**：任何语言只要能起 HTTP Server + 打印端口号即可
- **manifest.json 即 UI**：声明组件类型 + 布局即可生成页面，35+ 种组件类型（chat、code-editor、data-table、chart、document、spreadsheet、presentation、video、map、calendar、lottery-wheel、form、type-check、flashcards、quiz、mindmap 等）
- **进程管理**：`ProcessManager` 自动管理四级 .exe 生命周期（启动 → PORT 解析 → health check → 优雅关闭）
- **能力发现**：`discoverCapabilities` 扫描子目录自动判定六维能力
- **事件通信**：`PageEventBus` 支持 slot 间事件通信（`slot:toggle`、`slot:switch_page`），无需 Dart 代码
