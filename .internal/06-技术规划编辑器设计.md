## 二、双轨交互模型详细设计

### 2.1 静默辅助轨（Ghost Text）— Phase 2

```
用户输入 "我们选择Flutter作为前端框架"
     ↓
光标右后方显示浅灰色幽灵文本：
"我们选择Flutter作为前端框架[，理由是其跨平台能力和热重载特性][（详见Flutter官方性能基准报告）]"
     ↓
用户按 Tab → 幽灵文本生效，光标跳到末尾
用户继续输入 → 幽灵文本自动消失
```

**实现方案**：
- 用 `Overlay` + `Positioned` 在 `re_editor` 光标位置后叠加 `Text` widget
- 颜色 `Colors.white38`，`letterSpacing` 对齐编辑器
- 监听编辑器 `onChanged`：有修改则清除幽灵文本
- 通过 Agent 调用后端推理生成补全

### 2.2 深度对话轨（@ai Trigger）— Phase 1

```
用户输入 @ai 此处需要确认WebSocket方案
     ↓
① 提取全文（含 @ai 后的指令）→ 传给 AI 助手
② AI 自动调研（web_search 工具 + 内部知识）
③ 右侧面板生成结构化技术分析报告：
   ├── 设计理解（Summary of user intent）
   ├── 可行性支撑（Evidence + citations）
   ├── 盲区补充（Risks user may have missed）
   ├── 新思路（Alternative approaches）
   └── 风险提示（仅确凿冲突时，否则不出现）
     ↓
④ 用户确认 AI 建议 → AI 直接改写文档
⑤ 进入左右对比栏 → 差异高亮 → 逐条 Keep/Discard
```

**右侧 AI 面板布局**：
```
┌─────────────────────────┐
│ 🔍 技术调研分析          │ ← 收起/展开
├─────────────────────────┤
│ 📋 设计理解              │
│ 用户意图是...            │ ← 可折叠区
├─────────────────────────┤
│ 📚 可行性支撑             │
│ • Flutter WebSocket...  │
│   [来源: dart.dev]       │ ← 带引用链接
├─────────────────────────┤
│ ⚠️ 盲区补充               │
│ 考虑断线重连策略...       │
├─────────────────────────┤
│ 💡 新思路                 │
│ 用 Riverpod Stream...   │
├─────────────────────────┤
│ [应用建议改写]  [忽略]    │ ← 操作按钮
└─────────────────────────┘
```

### P1-3：AI 技术分析 Skill（`ai_tech_skill.dart`）

## 五、技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 编辑器基础 | `re_editor`（已安装） | 语法高亮、折叠、快捷键均现成，无需新依赖 |
| Diff 算法 | `diff_match_patch`（新增） | Google 的 Myers diff，Python/JS/Dart 多语言，精确度高 |
| AI 集成 | 复用 `AgentAssembly`（import `lib/core/agent/`） | chat 组件已验证模式，零序列化开销 |
| 状态管理 | `ConsumerStatefulWidget` + 本地 State | 单组件级别，无需全局 Riverpod |
| 布局 | 三栏式：编辑器 | 预览 | AI 面板 | 桌面端最佳体验 |
| 追溯存储 | JSON 文件 → `.greenix/workspaces/<id>/traces/` | 轻量，与现有 workspace 体系一致 |
