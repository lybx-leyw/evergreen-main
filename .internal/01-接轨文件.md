## 我对这个项目的认知

### 一句话定位

**Evergreen** 是一个 Flutter 桌面应用——无账号、无服务端、本地优先、AI 原生、去中心化微工具集成平台。目标用户是大学生。

插件开发门槛从"学 Flutter 全栈开发"降到了"写 JSON + 写 .exe"——任何能编译出可执行文件的语言都能写插件。对 AI 极度友好：逻辑简单、脚本语言 AI 足够擅长，用户用自然语言就能让 AI 直接生成成品插件。

### 架构心智模型：上中下游三层

```
上游 core/          中游 plugins/           下游 renderer/
══════════          ═══════════════         ════════════════
纯 Dart 服务层      插件 = JSON + .exe       纯 Flutter 渲染层
─────────────────────────────────────────────────────────────
提供原子能力         决定页面形态              按声明画 UI
Agent 运行时          manifest.json 声明       ModuleDispatch 派发
Tool 注册              ui 范式/布局/slot        widgets/ 原子组件
Config 引擎            数据绑定/交互规则         shared/ 范式视图
Data 管线              .exe 跑业务逻辑           compositions/ 叠加
Module 注册中心         HTTP 调用上游服务
Theme 引擎
```

**数据流向**：`上游 core/ ←──HTTP JSON 调用── 中游 plugins/ ──descriptor/Riverpod→ 下游 renderer/`

**各层的"不"**：
- 上游不画像素（纯 Dart，无 Flutter 依赖）
- 中游不写 Dart UI 代码（只需 JSON + .exe）
- 下游不解析 manifest 管理进程，不写业务逻辑

### main.dart 的角色

横跨三层的组装者：启动 6 个内部 HttpServer → 扫描插件 → 解析 manifest → 注册到 ModuleRegistry → 启动 .exe → seal → 注入 Riverpod → runApp。

### 下游的双渲染模式

| 模式 | 引擎 | 能力 | 定位 |
|------|------|------|------|
| `dart`（默认） | Flutter Widget 树 | 完整功能 | 主渲染路径 |
| `html` | WebView 内嵌 HTML | 完整功能 | 供AI诊断 |

Dart 路径可直接 `import core/` 零序列化调用——这是 Dart 下游最原生、最高效的原因。提供了三条快速通道：

- **agent 快速通道**：`shared/chat_controller_view.dart`、`multi_agent/single_agent_column.dart`、`shared/chat_view.dart` 等直接 import `core/agent/`，封装 AI 助手组件
- **data 快速通道**：`shared/data_dashboard_view.dart` 直接 import `core/data/data.dart`，提供数据中枢面板
- **config 快速通道**：`shared/settings_view.dart` 直接 import `core/config/settings.dart`，提供设置页面封装

### 关键设计决策

- **JSON 声明 + HTTP 通信**：降低创作门槛
- **端口发现文件**：`.agent_port` `.config_port` `.core_port` `.data_port` `.module_port` `.theme_port`，文件系统即注册中心
- **标准 .exe 契约**：随机端口 → stdout `PORT:xxxx` → HTTP JSON 通信 → `/health`
- **register → seal 模式**：`ModuleRegistry` 三段生命周期，路由启动后不可变
- **四级进程层级**：模块级 → 页面级 → 栏位/组件级 → 动作级，各层独立 .exe
- **dataSource 数据绑定**：与进程解耦的定时拉取管线，声明 endpoint + refreshInterval
- **V2 composite 模式**：5 种布局范式 + 35+ 组件类型，纯 JSON 声明，按 pages/workspace 自动选择视图
- **Agent 主循环**：Controller.send → Compactor → compose → Provider.chat → Tool Execution（Gate → StormBreaker → call）→ FinalReadiness → MemoryAgent 事后提取
- **四道安全网**：Gate（权限门控）→ StormBreaker（风暴抑制）→ FinalReadiness（最终检查）→ Compactor（上下文压实）
- **AgentFactory**：多 Agent 隔离实例，每个独立 Session/Memory/Tool 白名单
- **Memory 三作用域**：conversation（内存）→ feature（模块隔离）→ global（文件持久化），MemoryAgent 自动提取用户特质
- **Skill**：Markdown 技能包，inline/subagent 双模式，SkillGenerator 支持自然语言生成

### 六维插件模型

一个插件目录可同时包含多种类型，各子目录互不冲突：

| 子目录 | 包含 | 被谁加载 |
|--------|------|---------|
| `agent/` | manifest.json + .exe | PluginBridge → toolRegistry |
| `module/` | manifest.json | ModuleLoader → ModuleRegistry |
| `theme/` | theme.json | ThemeLoader → ThemeStore |
| `data/` | manifest.json + .exe | DataSourceLoader → DataOrchestrator |
| `config/` | config.json | SettingsLoader → SharedPreferences |
| `skill/` | `*.md` | SkillLoader → SkillIndex |
