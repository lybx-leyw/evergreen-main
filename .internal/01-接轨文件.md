## 我对这个项目的认知

### 一句话定位

**Evergreen** 是一个 Flutter 桌面应用——无账号、无服务端、本地优先、AI 原生、去中心化微工具集成平台。目标用户是大学生。核心价值主张："一个 Python 学生，一杯咖啡，一页 JSON，一个完整的 AI 助手"。

### 架构心智模型：上中下游三层

这是理解整个项目最关键的思维模型：

```
上游 core/          中游 plugins/           下游 renderer/
══════════          ═══════════════         ════════════════
纯 Dart 服务层      插件 = JSON + .exe       纯 Flutter 渲染层
─────────────────────────────────────────────────────────────
提供原子能力         决定页面形态              按声明画 UI
Agent 运行时          manifest.json 声明       ModuleDispatch 派发
Tool 注册              ui 范式/布局/slot        widgets/ 原子组件
Config 引擎            数据绑定/交互规则         shared/ 范式视图
Data 管线              .exe 跑业务逻辑           compositions/ 叠加
Module 注册中心         HTTP 调用上游服务
Theme 引擎
```

**数据流向**：`上游 core/ ←HTTP JSON 调用→ 中游 plugins/ ←descriptor/Riverpod→ 下游 renderer/`

**各层的"不"**：
- 上游不画像素（纯 Dart，无 Flutter 依赖）
- 中游不写 Dart UI 代码（只需 JSON + Python/.exe）
- 下游不解析 manifest，不管进程，不写业务逻辑

### main.dart 的角色

横跨三层的组装者：启动 6 个内部 HttpServer → 扫描插件 → 解析 manifest → 注册到 ModuleRegistry → 启动 .exe → seal → 注入 Riverpod → runApp。

### 关键设计决策

- **JSON 声明 + HTTP 通信**：降低创作门槛
- **端口发现文件**：`.agent_port` `.config_port` 等，文件系统即服务发现
- **register → seal 模式**：路由启动后不可变
- **composite 是终局范式**：页面→栏目→内容组件的纯 JSON 声明，取代所有预设范式
- **PluginBridge 三种 argMode**：stdin / args(flag/positional/json)
- **Agent 主循环**：Compose → LLM Call → Record → Execute Tools → FinalReadiness
- **三道安全网**：Gate（权限门控）→ StormBreaker（风暴抑制）→ FinalReadiness（最终检查）

### 六维插件模型

一个插件目录可以包含：agent/ module/ theme/ data/ config/ skill/——各子目录独立运作、互不冲突。

### 可写范围（AI 协作规则）

| 层级 | 可修改 |
|------|--------|
| 上游 core/ | `core/` 下非 agent/config/data/module/theme 的内容 |
| 上游子模块 | 仅限被指定的那个（agent 或 config 或 data 等） |
| 中游 plugins/ | 示例插件（`lib/core/*/example/plugins/` 和 `plugins/`） |
| 下游 renderer/ | 全部；只读 core/ |
| 全局 | `lib/` 根文件、`scripts/`、`windows/`、根级配置 |
