# 上游说明——core/ 纯 Dart 服务层

> 对应源码目录：`evg-base/lib/core/`

---

## 位置

```
evg-base/lib/core/
├── agent/          ← AI Agent 运行时（主循环、工具、记忆、技能、控制器、会话、Provider）

├── data/           ← 数据谱仪器（DataOrchestrator + DataHttpServer）
```

## 原理

### 1. 上游核心定位

上游是整个平台的**服务层和声明引擎**。它：
- 提供所有原子能力（Agent 对话、配置管理、模块注册、主题解析、数据管线）
- 以 **HTTP API** 的形式向外暴露服务（6 个内部 HttpServer）
- **不引用 Flutter Widget**（除极少数 Design Tokens 相关的枚举类型外）
- 可脱离 Flutter 独立编译和测试

### 2. 六服务器架构

| 服务器 | 文件 | 端口文件 | 职责 |
|--------|------|---------|------|
| CoreHttpServer | `services/core_http_server.dart` | `.core_port` | OCR + 更新 + 插件安装 |
| ConfigHttpServer | `config/config_http_server.dart` | `.config_port` | 设置/权限/插件源 CRUD |
| DataHttpServer | `data/data_http_server.dart` | `.data_port` | 数据源查询 |
| ThemeHttpServer | `theme/theme_http_server.dart` | `.theme_port` | 主题管理 |
| AgentHttpServer | `agent/tools/agent_http_server.dart` | `.agent_port` | AI 对话 SSE 代理 |
| ModuleHttpServer | `module/module_http_server.dart` | `.module_port` | 模块注册查询 |

全部绑定 `InternetAddress.loopbackIPv4`（仅本地可访问），端口由 OS 自动分配（`port: 0`），通过 `.xxx_port` 文件发现。

### 3. 端口发现机制

Python 插件通过读取端口文件来发现后端服务：
```python
def _read_port(name):
    path = os.path.join(_PROJECT_ROOT, name)
    if os.path.isfile(path):
        with open(path) as f:
            return f.read().strip()
    return None
```

### 4. Agent 运行时（最重要的子系统）

**核心链路**（一轮对话）：

```
Controller.send(input)
  ├── 自动读取全局记忆 → Session
  └── Agent.run()
        ├── ⓪ Compactor.check()          ← 上下文压实（四级阈值：soft/compact/force）
        ├── ① compose()                  ← 拼装 system prompt + 工具 schema + 记忆 + Skill
        ├── ② Provider.chat()            ← 流式 SSE 调用 DeepSeek API
        ├── ③ 记录 assistant 消息 → Session
        ├── ④ Tool Execution             ← Gate → StormBreaker → pre-hook → Registry.call() → post-hook
        │     └── 有工具调用 → continue 循环
        └── ⑤ FinalReadiness.check()     ← 有工具但无文本回答 → 重试（最多 3 次）
              └── 通过 → 产出最终回答
事后：MemoryAgent 自动提取用户特质 → 写入文件
```

**关键子组件**：

| 组件 | 文件 | 说明 |
|------|------|------|
| **Provider** | `agent/provider.dart` | LLM API 抽象，`DeepSeekProvider`：流式 SSE + 指数退避重试 + tool_calls delta 合并 |
| **Registry** | `agent/tool.dart` | 工具注册表，`register()` / `enable()` / `disable()` / `call()` |
| **Controller** | `agent/controller/controller.dart` | 状态机 `idle → running → awaitingApproval`，`send()` / `approve()` / `cancel()` |
| **Session** | `agent/session.dart` | 对话历史，含 token 统计 |
| **Memory** | `agent/memory/memory.dart` | 三作用域架构：conversation（内存）→ feature（模块隔离）→ global（文件持久化，`MEMORY.md` 索引） |
| **MemoryAgent** | `agent/memory/memory_agent.dart` | 基于奥尔波特特质理论，每轮对话后自动提取用户特质写入文件 |
| **Skill** | `agent/skill/skill.dart` | Markdown 技能包，`SkillLoader` 三级扫描，`SkillIndex` 优先级覆盖 |
| **SkillGenerator** | `agent/skill/skill_generator.dart` | 自然语言 → LLM 生成 Skill Markdown |
| **Compactor** | `agent/compact/compact.dart` | AI 驱动上下文压实，保留 head + tail + LLM 摘要 |
| **StormBreaker** | `agent/agent/agent.dart` (L61-86) | 写工具重复调用计数，同一错误签名 ≥3 次自动压制，同工具成功 ≥5 次也压制 |
| **Gate** | `agent/agent/gate.dart` | 权限分层 `always > confirm > approve > deny`，通配符匹配 |
| **FinalReadiness** | `agent/agent/agent.dart` (L101-115) | 有工具调用但无可见回答 → 重试，最多 3 次 |
| **PluginBridge** | `agent/tools/plugin_bridge.dart` | 扫描 `plugins/<name>/agent/` → 注册为 `PluginTool`，三种 argMode：stdin/flag/positional |
| **AgentFactory** | `agent/agent_factory.dart` | 多 Agent 隔离实例：每个独立 Session、Memory、SkillIndex、Tool 白名单（all/specific/none） |

### 5. Module 子系统

**ModuleDescriptor**：整个模块系统的核心数据结构（`module/module_descriptor.dart`，~2600+ 行），包含 30+ 个子描述符类（`PageDescriptor`、`SlotDescriptor`、`ComponentDescriptor`、`LayoutDescriptor`、`LayoutPreset`、`LayoutFeatures` 等）。所有描述符都是 const 构造 + `fromJson`/`toJson`。

**ModuleRegistry**（`module/module_registry.dart`，325 行）：三段生命周期——
1. 注册期：`register()` / `registerAll()` / `setCapabilities()`（写开放，读禁止）
2. 密封：`seal()` 设置 `_sealed = true`，`_validateDependencies()` 校验依赖
3. 查询期：`findById()` / `findByRoute()` / `navGroups` / `search()`（读开放，写禁止）

**ModuleLoader**（`module/module_loader.dart`，251 行）：`scanModules()` 扫描 `plugins/<name>/module/manifest.json` → `scanAndLoadModules()` 启动 .exe → 解析 stdout `PORT:(\d+)` → health check → 注册到 Registry。

**ProcessManager**（`module/process_manager.dart`，430 行）：按四级作用域管理进程生命周期——`startModule()` / `startPage()` / `startSlot()` / `runAction()`，每个作用域启动独立的 `_ManagedProcess`。

**Capability 发现**：`module/capability.dart` 中 `discoverCapabilities()` 自动扫描插件子目录判定六维能力。

### 6. 其他子系统

**Config**（`config/`）：`initSettings()` 扫描内置和插件 `config/config.json`，`getSetting()` / `setSetting()` 读写 SharedPreferences。`ConfigHttpServer` 暴露 8 个 REST 端点。

**Data**（`data/`）：`DataOrchestrator` 管理数据源注册与查询，`DataSourceLoader` 扫描 `plugins/<name>/data/manifest.json` 并启动 .exe 进程。支持 remote manifest 拉取。

**Theme**（`theme/`）：`ThemeStore`（ChangeNotifier）管理主题状态，`ThemeLoader.scanThemes()` 扫描 `theme/theme.json`。10 个内置主题位于 `lib/core/theme/builtins/`。

## 效果

- **core/ 可脱离 Flutter 独立运行**（通过 `--dart-define=EVERGREEN_TEXT_MODE=true` 文本模式）
- **纯 Dart 测试无需 Flutter SDK**（`dart run test` 而非 `flutter test`）
- **Stub 包隔离**使各模块可独立 `dart analyze`
- **声明驱动**：所有配置通过 `*Descriptor` 不可变类传递，无运行时可变状态
- **未知字段静默忽略**：收到未识别 JSON 字段不抛异常，保证容错
- **启动顺序严格**：HttpServer 先启动并写入端口文件 → 启动模块 .exe → ModuleRegistry seal → runApp
