# 上游说明——core/ 纯 Dart 服务层

> 对应源码目录：`evg-base/lib/core/`

---

## 位置

```
evg-base/lib/core/
├── agent/          ← AI Agent 运行时（主循环、工具、记忆、技能、控制器、会话）
├── config/         ← 配置引擎（设置/权限/插件源）
├── data/           ← 数据谱仪器（DataOrchestrator + DataHttpServer）
├── module/         ← 模块注册中心（ModuleRegistry + ModuleLoader + ModuleDescriptor）
├── theme/          ← 主题引擎（ThemeStore + ThemeLoader + ThemeHttpServer）
├── services/       ← 通用服务（OCR、更新、CoreHttpServer）
├── utils/          ← 工具函数（Greenix 路径、文件操作）
├── lib/            ← Stub 包（独立 dart analyze，不参与编译）
├── docs/           ← 交叉文档
├── scripts/        ← 构建脚本
├── test/           ← 纯 Dart 单元测试
├── errors.dart     ← 错误类型
├── log.dart        ← 日志系统
└── core_text_app.dart ← 文本模式入口
```

## 原理

### 1. 上游核心定位

上游是整个平台的**服务层和声明引擎**。它：
- 提供所有原子能力（Agent 对话、配置管理、模块注册、主题解析、数据管线）
- 以 **HTTP API** 的形式向外暴露服务（6 个内部 HttpServer）
- **不引用 Flutter Widget**（除极少数 Design Tokens 相关的枚举类型外）
- 可脱离 Flutter 独立编译和测试

### 2. 六服务器架构

| 服务器 | 文件 | 端口文件 | 职责 |
|--------|------|---------|------|
| CoreHttpServer | `services/core_http_server.dart` | `.core_port` | OCR + 更新 + 插件安装 |
| ConfigHttpServer | `config/config_http_server.dart` | `.config_port` | 设置/权限/插件源 CRUD |
| DataHttpServer | `data/data_http_server.dart` | `.data_port` | 数据源查询 |
| ThemeHttpServer | `theme/theme_http_server.dart` | `.theme_port` | 主题管理 |
| AgentHttpServer | `agent/tools/agent_http_server.dart` | `.agent_port` | AI 对话 SSE 代理 |
| ModuleHttpServer | `module/module_http_server.dart` | `.module_port` | 模块注册查询 |

全部绑定 `InternetAddress.loopbackIPv4`（仅本地可访问），端口由 OS 自动分配（`port: 0`），通过 `.xxx_port` 文件发现。

### 3. 端口发现机制

Python 插件通过读取端口文件来发现后端服务：
```python
def _read_port(name):
    path = os.path.join(_PROJECT_ROOT, name)
    if os.path.isfile(path):
        with open(path) as f:
            return f.read().strip()
    return None
```

### 4. Agent 运行时（最重要的子系统）

**核心链路**（一轮对话）：
```
Controller.send(input)
  → Agent.run()
    → ⓪ Compactor.check()      [上下文压实]
    → ① compose()              [构造 system prompt + 工具列表 + 记忆 + 会话历史]
    → ② Provider.chat()        [流式 SSE 调用 DeepSeek API]
    → ③ 记录 assistant 消息到 Session
    → ④ 执行 tool_calls        [Gate → StormBreaker → ToolHooks → Registry.call()]
    → ⑤ FinalReadiness.check() [工具调用后是否有可见回答？无则重试]
    → AgentEvent 通过 EventSink 发射
```

**关键子组件**：
- **Provider**：LLM API 抽象，当前实现是 DeepSeekProvider（流式 SSE + 指数退避重试 + tool_calls delta 合并）
- **Registry**：工具注册表，支持注册/启用/禁用
- **Controller**：状态机 idle→running→awaitingApproval→idle
- **Session**：对话历史，含 token 统计
- **Memory**：三 scope 记忆（user/feedback/project/reference），文件存储 + MEMORY.md 索引
- **Skill**：Markdown 提示词技能包，三级优先（builtin < global < custom < project）
- **Compactor**：AI 驱动的上下文压缩
- **StormBreaker**：重复调用风暴抑制（同工具连续失败 3 次 / 成功 2 次即拦截）
- **FinalReadiness**：空答案检测，最多重试 3 次
- **PluginBridge**：扫描 `plugins/<name>/agent/` → 注册为 PluginTool

### 5. Module 子系统

**ModuleDescriptor**：整个模块系统的核心数据结构（`module/module_descriptor.dart`，~2200+ 行），包含 40+ 个子描述符类（PageDescriptor、SlotDescriptor、ComponentDescriptor、LayoutDescriptor、所有 UI 范式 Options 等）。所有描述符都是 const 构造 + fromJson/toJson。

**ModuleRegistry**：收集 ModuleDescriptor → seal() 锁定 → 生成路由/导航/命令面板条目。

**ModuleLoader**：扫描 `plugins/<name>/module/manifest.json` → 解析 → 启动 .exe → 解析 PORT 输出 → health check。

**Capability 发现**：自动扫描插件子目录判断能力维度（agent/module/theme/data/config/skill）。

## 效果

- **core/ 可脱离 Flutter 独立运行**（通过 `--dart-define=EVERGREEN_TEXT_MODE=true` 文本模式）
- **纯 Dart 测试无需 Flutter SDK**（`dart run test` 而非 `flutter test`）
- **Stub 包隔离**使各模块可独立 `dart analyze`
- **声明驱动**：所有配置通过 `*Descriptor` 不可变类传递，无运行时可变状态
- **未知字段静默忽略**：收到未识别 JSON 字段不抛异常，保证容错
- **启动顺序严格**：HttpServer 先启动并写入端口文件 → 然后启动模块 .exe → ModuleRegistry seal → runApp
